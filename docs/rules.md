# 游戏规则

> 适用于 GitHub 上的人类版源码和 v1.2.27 发行版。

## 怎么启动

从项目根双击 `开始游戏！.bat`，或者在终端执行 `python run.py`。推荐使用本发行版验证过的 Python 3.14。WPF 主界面需要 .NET 8 Desktop Runtime，使用 tkinter 备用界面时需要 Tcl/Tk。

终端依次确认免责声明、玩家名、随机事件、优惠融资、老虎机与开始确认。随机事件默认关闭，两项功能未预设时也默认关闭。`TM_EVENTS`、`TM_FR`、`TM_SLOT` 可用 `1` / `0` 预设。进入窗口后先答复挑战任务，再抽取难度。难度定档即开始计时，打开规则窗可以查看规则，计时仍继续。参见[主页](../README.md)。

## 难度、风险与快进

黑天鹅频率和市场深度各有五档。每个品种每个行情步的基础跳空概率分别为 0.24%、0.60%、1.50%、3.75%、9.38%，基础跳空幅度为 2%–12%。市场深度为 3,200 万、1,600 万、800 万、400 万或 200 万 Tokens，局内还会变化。成本估算和保证金口径见[成本模型](cost-model.md)。

开仓、借款、投注和快进须等定档。定档后下单还会检查可用保证金与维持保证金。维持保证金以总名义敞口乘基础比例 10% 和当前保证金倍数计算。覆盖水平低于 100% 进入追缴，低于 50% 立即强平。若现金为负但净值非负，可在默认 60 秒内借款补足现金；真正穿仓时净值为负，会触发结算。

| 快进档位 | 推进量 | 冷却 |
|---|---:|---:|
| 5 分钟 | 300 秒 | 120 秒 |
| 3 分钟 | 180 秒 | 90 秒 |

每局共 900 秒额度，两档可混用。额度不足或冷却中时无法使用该档。冷却期间行情继续。

## 优惠融资和老虎机

两项在开局前设置，开局后可关闭。借款会增加现金与欠款，不直接增加净值。贷款池基础值 300 万 Tokens，可贷额度等于当前贷款池减未还余额，贷款利息另计。每笔贷款的目标上浮取决于累计借入额和随机扰动。优惠融资把标准下限从 1% 降到 0.01%，拆单结果仍会因各笔抽样不同而变化。

老虎机单次投入 1–200,000 Tokens，并且不能超过现金余额，整局最多 3 次。返还概率为 80% 无返还、15% 返还 5 倍、5% 返还 10 倍。每笔中奖返还各自按 −5% 至 +100% 抽取目标调整比例。「孤注一掷」把借款和中奖返还的比例改为 +50% 至 +100%。

## 界面和结算

- 「投资界面」可开仓、按选中方向平仓、借还款、快进和重开。选择「重开一局」会替换当前局面，保留历史战报。
- 「结束结算」前请先核对持仓。已达目标且仍有持仓时，先平仓并重新确认净值。未达目标时结束会记录弃权并清算。v1.2.27 的服务收到结算请求后即安排停服，包括被拒绝的请求。
- 「结束相关进程」用于异常停服。它写的是快照，和正常结算是两种结果。
- HTML 和 JSON 摘要分别保存在 `src/data/reports/HTML Reports/` 和 `src/data/reports/JSON Reports/`。

## 挑战任务（PvZ2 关卡目标移植）

**开局第一件事**就是回答一句：**本局是否开启挑战任务？**
75 秒内 `POST /challenge/accept` 或 `POST /challenge/decline`，超时按「不开启」处理。

开启后随机给出 **3 条目标**，开局抽定、本局不再改变。判定贯穿整局：破功立刻打 ×（不可逆），
达标立刻打 √（可以提前完成）。

### 任务池

| 目标 | 判定口径 | 三档阈值（低 / 中 / 高难度） |
|---|---|---|
| 两袖清风 | 全程不向贷款池借入资金 | — |
| 毫发无伤 | 对局中不触发保证金强平 | — |
| 自食其力 | 不使用「外部的怜悯」求助（**仅 AI 版**：人类版没有这项功能，任务池已排除） | — |
| 从一而终 | 同一货币对不得同时持有多空 | — |
| 精打细算 | 累计手续费不超过本金的 X | 1.5% / 1.0% / 0.7% |
| 稳如磐石 | 净值最大回撤不超过 X | 18% / 12% / 8% |
| 轻装上阵 | 同时持仓不超过 X 条仓位（同品种多空分开计） | 4 / 3 / 2 |
| 留有余地 | 有持仓时保证金水平从不低于 X | 150% / 180% / 220% |
| 按兵不动 | 至少 X 笔平仓持仓满 5 tick | 1 / 2 / 3 |
| 更上层楼 | 净值达到当前目标的 X，可在局中记为达成 | 120% / 150% / 200% |
| 孤注一掷 | 净值达到已翻倍的当前目标，可在局中记为达成 | 目标 ×2；老虎机与借款的目标上浮固定 50%~100% |

三条抽取规则：

> **人类版的差异**：人类版没有「外部的怜悯」（那是 AI 版向观众席求助的通道），
> 所以「自食其力」在人类版永远不会被违反 —— 它被排除在抽取池之外，剩 10 条参与抽取。

- **必含至少一条结果型**（按兵不动 / 更上层楼 / 孤注一掷）：三条全是「不许做某事」会把玩法压成什么都不做
- 三条互不重复；「孤注一掷」与「更上层楼」互斥——目标已经翻倍，再叠 200% 就是 4 倍，同局出现等于必败
- 阈值按难度档取：`档位 = max(黑天鹅档, 流动性档)`，0–1 用宽松列、2 用中列、3–4 用严苛列

### 三种状态

| 标记 | 含义 |
|---|---|
| √ | 已达成（结果型可以提前达成，之后不再变化） |
| × | 已破功（过程型一旦违反即永久失败，之后不再恢复） |
| · | 进行中 |

局终清算会补齐所有任务，不会停在「进行中」：过程型（不借款 / 不爆仓 / 不求助 / 不对锁 /
手续费 / 回撤 / 持仓数 / 保证金）全程未破功即记为达成；结果型任务可在局中达成并锁定标记。结算时仅补判仍在进行中的结果型任务。

观众席右栏「挑战任务」卡片实时显示三条目标的名称、判定口径、当前状态与破功原因；
事件流同时记带 `【挑战任务】` 前缀的条目。参赛者拒绝开启时，卡片固定显示
「本局游戏参赛者未开启挑战任务」。

三条边界：

- **询问期的等待不计入 45 分钟**：答复（或超时）那一刻才重置计时基准
- **破功不可逆**：一旦打 ×，后面再守规矩也不会变回 · 或 √
- 「孤注一掷」改变目标以及贷款和中奖返还的上浮比例，其余挑战增加附加目标。

### 一大波预警（突发大事件）

开启随机事件后，开局以各 25% 的概率抽出 0–3 次预警。第 30 个行情步起才可能触发。常规阶段两次预警至少隔 36 步，满足间隔的每步有 1% 概率触发。最后三分钟会缩短间隔并取消概率门槛，提前结算仍可能留下未触发次数。

第 `t` 步出现预警横幅，WPF 同时播放 Windows 系统提示音。预警期间不投放普通新闻，价格仍会变动，也可能跳空。第 `t+2` 步集中触发 3–5 条冲击事件。正常两步约 10 秒，快进或行情加速会缩短实际反应时间。

`huge_wave.total` 为抽到的总次数，`fired` 按预警开始的次数计，`left` 为尚未触发。预警给出发生时点，方向和量级要等爆发才知道。

## 平台限制类事件（随机触发）

| 事件 | 持续 | 禁什么 | 例外 |
|---|---|---|---|
| 风控审查 | 60 步（常速约 5 分钟） | 借款 | 现金为负的 60 秒自救窗口不受影响 |
| 交易所维护 | 1 步（常速约 5 秒） | 主动平仓 | 爆仓强平与比赛结束结算都不受影响 |
| 老虎机维护 | 96 步（常速约 8 分钟） | 老虎机投注 | — |

这三条都是纯随机触发，系统不会因为玩家正在关键操作而跳过。
