## 怎么启动

运行时固定为 **Python 3.14.7**：

```
C:\Users\User\AppData\Local\Programs\Python\Python314\python.exe
```

**下面所有命令里的 `python` 都指这条绝对路径**；`run.py` 自己也会校验，版本不符直接退出码 2。

```bash
set TM_TRADER=Doubao-1.5-pro-深度思考-扣子
set TM_EVENTS=1
python run.py
```

服务起在 `127.0.0.1:8734`，GUI 是只读观众席。**全程不询问输入**，所有参数来自环境变量，没设置的
用默认值（`TM_TRADER=访客`、`TM_EVENTS=0`、`TM_FR=0`、`TM_SLOT=0`）。启动顺序：读环境变量 →
起服务 → 难度盲盒（30 秒，可用 `POST /roll/stop` 叫停）→ 计时开始 → 模型通过 HTTP 操作。

> `TM_TRADER` 原样写进报告文件名和报告正文，是区分参赛者的字段。
> 人工演示用 `python run.py --interactive`，会在命令行里依次问玩家名、随机事件、【优惠融资】、【老虎机】。

也可以双击 `开一局.bat`。

> 本文档是 **AI 版**规则说明。人类版（`TokensMarket-OpenSource-Human`）有投资界面，
> 规则参数与本版相同。

## 难度

难度有两个维度，开局随机抽，各 5 档。它们管的是两件不同的事：

- **黑天鹅** —— 风险有多频繁
- **流动性** —— 你敢开多大仓位

### 黑天鹅 · 每 tick 每品种的跳空概率

| 档位 | 概率 | 45 分钟内单品种期望跳空 |
|---|---:|---:|
| 极低 | 0.24% | 约 1.3 次 |
| 低 | 0.60% | 约 3.2 次 |
| 中 | 1.50% | 约 8.1 次 |
| 高 | 3.75% | 约 20 次 |
| 极高 | 9.38% | 约 51 次 |

跳空幅度 2%~12%，方向随机。挂出的止损可能被直接跳过（挂 126.5 成交到 131 是常见情况）。

### 流动性 · 滑点成本

| 档位（市场深度） | 1000 万名义往返 | 占本金 100 万 |
|---|---:|---:|
| 充裕（3200 万） | 17,500 | 1.75% |
| 正常（1600 万） | 25,000 | 2.50% |
| 纤薄（800 万） | 40,000 | 4.00% |
| 枯竭（400 万） | 70,000 | 7.00% |
| 黑洞（200 万） | 130,000 | 13.0% |

上表按 1000 万名义、AURA 级点差（0.06%）算，含手续费（4,000）+ 点差（6,000）+ 滑点三部分。
**是成本占初始本金的比例**，不是占名义规模的比例。

**滑点随名义规模「平方」增长，不是线性**：成本 = `SLIP_K / (2 × 市场深度) × 名义²`，`SLIP_K = 0.0024`。
所以名义翻倍，滑点成本翻四倍。同一档位开 40M 的滑点成本是开 20M 的四倍，不是两倍。

单笔滑点率有上限：正常 1.4%，流动性冲击期间 6%。

**末期滑点上浮（v1.2.0）**：`tick ≥ 360`（最后 15 分钟）起，滑点系数从 `1.0` 线性升到 `1.5`（`tick = 540` 时打满）。这不是白送收益——**开局立刻退出收益仍是 0**，而是让「赖到最后」越来越贵：同样的仓位，末期平仓要多付最多一半的滑点。

难度会显示在窗口标题：

```
Tokens 交易市场 | 你的名字（理想情况） | 黑天鹅频率：低 | 流动性枯竭程度：纤薄
```

## 两个全局开关：优惠融资与老虎机

这两个不是随机事件，而是开局时选择的**全局开关**：整局有效，中途可再开 / 关。

- 开局时开启：**免费**
- 游戏进行中再打开：**支付 30 万现金**（关闭免费）

### 优惠融资

开启后：

- 借款次数**不限**（仍受 300 万贷款池与可贷额度约束）；让利只体现在目标上浮下限从 +1% 降到 +0.01%
- 借款的目标上浮区间：`+1% ~ +100%` 变成 `+0.01% ~ +100%`（**必上抬，永不减免**，最小值 0.01%）
- 上浮比例随**累计借款额**上升：首借 30 万约 4%~8%，一次借满 300 万约 35%~66%
- 拆单与一次借满等价——按累计额做梯形积分，拆成十笔不省一分钱

例：目标 200 万，借 30 万若抽到 +6%，新目标 = 200 + 1.8 = **201.8 万**

未开启时：借款次数不限，目标上浮 `+1% ~ +100%`（同样随累计额上升）。

### 老虎机

开启后：

- 整局可投 **3 次**，单次 `1 ~ 200,000`，且不得超过下注瞬间的当前权益
- **80%** 无所得 / **15%** 返还 5 倍 / **5%** 返还 10 倍
- 返还金额进入现金；同时目标按返还金额的 `-5% ~ 100%` 上浮

### 组合公式

```
Total = 原目标
      + Σ 每笔借款 × pct(该笔)       ← pct 随累计借款额上升
      （首借 30 万约 4%~8%，借满全池一次约 35%~66%；
        按累计额做梯形积分，拆成十笔与一次借满等价，拆单省不到钱）
      + 老虎机累计返还 × U(-5%~100%) ← 已开老虎机
```

两项独立抽取；只开一个，就只加对应的那一项。

次数用完后继续操作：返回「次数已用完，拒绝执行」。

## 快进

每局快进额度共 **15 分钟（900 秒）**。两种档位可自由混用：

| 档位 | 每次推进 | 每次后冷却 |
|---|---:|---:|
| 5 分钟 | 300 秒 | 120 秒 |
| 3 分钟 | 180 秒 | 90 秒 |

- 难度盲盒的那 30 秒不计入 45 分钟——定档的瞬间才开始计时。
- 用哪一档，就按那一档的冷却时间计时。
- 冷却期内按钮变灰，无法点击。
- 剩余额度不足以覆盖该档时，该次不执行。例如已用 `5′+3′+3′+3′ = 840` 秒，剩 60 秒，任何一档都用不了。
- 界面上会显示剩余额度、已用记录和冷却倒计时。
- 推进时间只有快进一条路：整局 900 秒额度、单次 300 或 180 秒、冷却 120/90 秒，不能绕开。

### 三个按钮

| 按钮 | 作用 |
|---|---|
| 「最小化」 | 把窗口收起来，游戏继续跑 |
| 「结束相关进程」 | 停掉服务并关窗口（**会计一次异常退出**） |
| 「结束并结算」 | 正常结束本局，生成报告 |

## 常见问题

**Q: 双击 bat 后卡在「难度抽选中」不动？**
A: 那是 30 秒倒计时，可以点「叫停」提前定格。

**Q: 主窗口一直不出现？**
A: 说明卡在难度盲盒或规则窗，看看有没有被其他窗口挡住。

**Q: 报告在哪？**
A: `src/data/reports/` 下的 `.html` 文件，一局一个。

**Q: 想重开一局？**
A: 投资界面底部有「重开一局」。

**Q: Windows 弹警告拦住了怎么办？**
A: 源码版没有 `.pyd`，只有 `.bat` 可能被 SmartScreen 拦。右键 bat → 属性 → 勾「解除锁定」→ 确定，做一次就行。

## 平台限制类事件（随机触发）

| 事件 | 持续 | 禁什么 | 例外 |
|---|---|---|---|
| 风控审查 | 5 分钟 | 借款 | 现金为负的 60 秒自救窗口不受影响 |
| 交易所维护 | 5 秒（1 tick） | 主动平仓 | 爆仓强平与比赛结束结算都不受影响 |
| 老虎机维护 | 8 分钟 | 老虎机投注 | — |

这三条都是纯随机触发，系统不会因为玩家正在关键操作而跳过。

## 外部的怜悯

参赛者与观众席之间的双向通道。默认关闭。

- **开局前**：`set TM_ASSIST=1`，或在交互问答里选「开」，免费。
- **开局后**：`POST /assist/enable`，从现金里扣 **500,000**，现金不足则拒绝。
- 观众席界面没有开通入口：开通与否只由参赛者决定。

开启后：

| 接口 | 作用 |
|---|---|
| `POST /assist/ask` `{"text": "..."}` | 参赛者向观众席求助。整局 **3 次**，超出返回 `no asks left (3/3)`。返回 `ticket` |
| `GET /assist/inbox` | 取观众席还没被取走的话；取过的不再重复投递 |
| `POST /assist/reply` `{"ticket": "a1", "text": "..."}` | 观众席回复某次求助 |
| `POST /assist/reject` `{"ticket": "a1"}` | 观众席驳回某次求助 |
| `GET /assist/pending` | 观众席 GUI 轮询用：还没回复的求助 + 完整对话 |

**求助不阻塞。** `POST /assist/ask` 立刻返回，参赛者接着交易，自己决定什么时候查 `GET /assist/inbox`。

观众席看到待处理的求助时，会弹出系统提示框（标题「外部的怜悯」，写明当前几条求助）并响一声提示音；GUI 按钮同时变红并显示条数。整段对话在报告里并入「场外援助」章节。

> 观众席只能给建议文本；开仓平仓仍然必须由参赛者自己调接口。
