# 游戏规则

> **中文** · [English](rules.en.md)

> 适用于中文开源 AI 版 v1.2.29。

## 怎么启动

从项目根目录用 Python 3.14 启动。入口命令见 [AGENTS.md](../AGENTS.md)。`python run.py` 读取环境变量并打开观众席，交互演示入口另有终端问答。新局先通过 HTTP 答复挑战（75 秒，超时按拒绝），然后等待 30 秒盲盒或提前定档。定档后开始 45 分钟计时。

`TM_TRADER` 用于记录参赛者。确认 `rolled:true` 后再交易。无活动保护开启时，按行情步计算距上次成功状态变更的间隔。脚本入口默认关闭，双击入口默认 12 分钟。命令示例见[接入协议](ai-protocol.md)。

## 难度

难度有两个维度，开局随机抽，各 5 档。它们管的是两件不同的事：

- **黑天鹅** —— 风险有多频繁
- **流动性** —— 你敢开多大仓位

### 黑天鹅 · 每 tick 每品种的跳空概率

| 档位 | 概率 | 540 个常速步内单品种期望跳空 |
|---|---:|---:|
| 极低 | 0.24% | 约 1.3 次 |
| 低 | 0.60% | 约 3.2 次 |
| 中 | 1.50% | 约 8.1 次 |
| 高 | 3.75% | 约 20 次 |
| 极高 | 9.38% | 约 51 次 |

跳空可能越过计划退出价。当前接口未提供挂止损单。

### 流动性 · 滑点成本

由充裕到黑洞的基础深度分别为 3,200 万、1,600 万、800 万、400 万和 200 万 Tokens，局内会按品种变化。滑点公式与开仓上限见[成本模型](cost-model.md)。

## 两个全局开关：优惠融资与老虎机

这两个不是随机事件，而是开局时选择的**全局开关**：整局有效。

- 只能在开局时决定；**对局一旦开始，就不能再打开**（关闭始终免费）
- 开局时开启免费

### 优惠融资

普通融资的目标上浮区间为 +1% 至 +100%，优惠融资把下限降到 +0.01%。两种模式都允许多次借款，额度受当前贷款池和未还余额约束，基础贷款池为 300 万。比例的基础值按本笔前后累计借入额占池比例的均值计算，每笔再加独立随机扰动，拆借同一总额的实际结果可以不同。

例如借 30 万抽到 +6%，目标增加 1.8 万。还款减少未还本金和后续利息。贷款按成本步对未还余额计 0.01% 复利，见[成本模型](cost-model.md)。

### 老虎机

开启后：

- 整局可投 **3 次**，单次 `1 – 200,000`，且不得超过下注瞬间的**可用现金**（不是权益：浮盈不算现金，用浮盈下注会把现金打成负数）
- **80%** 无所得 / **15%** 返还 5 倍 / **5%** 返还 10 倍
- 返还金额进入现金；同时目标按返还金额的 `-5% – 100%` 上浮

### 组合公式

`目标 = 初始目标 + Σ（每笔借款 × 本笔比例）+ Σ（每笔中奖返还 × 本笔比例）`。「孤注一掷」在定档时把当前目标翻倍，并把之后每笔借款和中奖返还的比例改为 50%–100%。

## 快进

每局快进额度共 **15 分钟（900 秒）**。两种档位可自由混用：

| 档位 | 每次推进 | 每次后冷却 |
|---|---:|---:|
| 5 分钟 | 300 秒 | 120 秒 |
| 3 分钟 | 180 秒 | 90 秒 |

- 难度盲盒的那 30 秒不计入 45 分钟——定档的瞬间才开始计时。
- 用哪一档，就按那一档的冷却时间计时。
- 冷却期内 `POST /fastforward` 返回 `ok: false`，`ff.cool_left` 给出剩余秒数。
- 剩余额度不足以覆盖该档时，该次不执行。例如已用 `5′+3′+3′+3′ = 840` 秒，剩 60 秒，任何一档都用不了。
- 余额与冷却看 `GET /state` 的 `ff` 字段：`used` / `remain` / `cool_left` / `can5` / `can3`。
- 正常行情在冷却期内仍会自动推进。

### 观众席窗口能做什么

AI 版观众席没有下单、快进或结算入口。窗口还提供最小化、报告查看与援助回复等功能。

| 操作 | 作用 |
|---|---|
| 最小化 | 把窗口收起来，对局继续跑 |
| 结束相关进程 | 停掉服务并关窗口（**会计一次异常退出**） |

正常结束本局走 `POST /quit`（结算并生成报告），不要用「结束相关进程」。
达到目标且有持仓时，先用 `POST /close_all` 平仓并核对新净值，再请求结算。v1.2.28 即使拒绝 `/quit` 也会安排停服。

## 常见问题

- 如果难度盲盒没开始，先检查挑战是否待答复，答复后才倒数。
- 观众席没出现时，检查启动终端、端口和[主页](../README.md)列出的桌面组件。
- 战报在 `src/data/reports/HTML Reports/` 与 `src/data/reports/JSON Reports/`。复现行情需相同种子、档位、引擎版本与事件设置。
- 服务仍在运行时可用 `/reset` 重开。停服后请重新启动。

## 挑战任务（PvZ2 关卡目标移植）

**开局第一件事**就是回答一句：**本局是否开启挑战任务？**
75 秒内 `POST /challenge/accept` 或 `POST /challenge/decline`，超时按「不开启」处理。
询问期间行情不动，对局计时和难度盲盒都还没起步，所以这段等待不占 45 分钟。

答复或超时后开始抽取难度。启用挑战后，定档时从 20 条候选中抽取 **一条结果任务和两条过程任务**，同时公布本局阈值。过程任务破功立即标记，交易里程碑可以提前达成，净值任务按最终清算判定。

### 任务池

| 目标 | 判定口径 | 三档阈值（低 / 中 / 高难度） |
|---|---|---|
| 两袖清风 | 全程不向贷款池借入资金 | — |
| 毫发无伤 | 对局中不触发保证金强平 | — |
| 自食其力 | 不使用「外部的怜悯」求助 | — |
| 从一而终 | 同一货币对不得同时持有多空 | — |
| 精打细算 | 累计手续费不超过本金的 X | 1.5% / 1.0% / 0.7% |
| 稳如磐石 | 净值最大回撤不超过 X | 18% / 12% / 8% |
| 轻装上阵 | 同时持仓不超过 X 条仓位（同品种多空分开计） | 4 / 3 / 2 |
| 留有余地 | 有持仓时保证金水平从不低于 X | 150% / 180% / 220% |
| 远离红线 | 全程避免追缴保证金和强平 | — |
| 低倍操盘 | 每次开仓、加仓的杠杆在上限内 | 30 / 20 / 10 倍 |
| 量力而行 | 多空合计名义敞口在上限内 | 本金的 3 / 2.5 / 2 倍 |
| 持仓有度 | 累计持仓费在上限内 | 本金的 2% / 1.4% / 0.9% |
| 远离赌桌 | 全程不投注老虎机 | — |
| 按兵不动 | 仓位最后一次开仓或加仓后持满 5 tick，再主动全部平掉 | 1 / 2 / 3 条 |
| 更上层楼 | 结算净值达到当前目标的一定比例 | 110% / 120% / 130% |
| 孤注一掷 | 结算净值达到届时目标，开局目标翻倍至 400 万 | 借款和老虎机返还按 50%～100% 上浮目标 |
| 积小成多 | 至少主动平仓一次，清算后获得正收益 | 本金的 3% / 5% / 8% |
| 见好就收 | 单笔主动平仓净收益达到门槛 | 本金的 1% / 1.5% / 2% |
| 多点开花 | 多个品种各自达到累计主动平仓净收益门槛 | 2 个各 0.2% / 2 个各 0.3% / 3 个各 0.5% 本金 |
| 多空皆宜 | 多单、空单各自达到累计主动平仓净收益门槛 | 各为本金的 0.3% / 0.5% / 0.8% |

三条抽取规则：

- 七条结果任务中，「孤注一掷」的抽中概率为 1/19，其余六条各为 3/19。
- 两条过程任务来自不同类别。未启用场外援助或老虎机时，跳过相应的禁用任务。
- 阈值按难度档取：`档位 = max(黑天鹅档, 流动性档)`，0–1 用宽松列、2 用中列、3–4 用严苛列

### 三种状态

| 标记 | 含义 |
|---|---|
| √ | 已达成（交易里程碑达成即锁定，净值目标在清算时判定） |
| × | 已破功（过程型一旦违反即永久失败，之后不再恢复） |
| · | 进行中 |

挑战会在行情推进和相关操作成功后即时检查。「见好就收」「多点开花」「多空皆宜」按主动平仓成交价计算净收益，扣除开平仓手续费，持仓费和借款利息另计。局终清算费计入手续费上限，清算造成的净值变化计入回撤。

观众席右栏「挑战任务」卡片实时显示三条目标的名称、判定口径、当前状态与破功原因；
事件流同时记带 `【挑战任务】` 前缀的条目。参赛者拒绝开启时，卡片固定显示
「本局游戏参赛者未开启挑战任务」。

三条边界：

- **询问与抽取难度均不占用 45 分钟**，正式计时从难度定档开始
- **破功不可逆**：一旦打 ×，后面再守规矩也不会变回 · 或 √
- 「孤注一掷」会调整目标、融资和中奖返还的目标上浮；其他挑战增加附加目标。

## 随机事件与一大波预警

随机事件池有 40 条，完整名称、作用范围、幅度和持续时间见 `GET /rules` 的「随机事件池」。「做市商撤单」和「深度回补」分别将有效市场深度调为 0.75 倍和 1.5 倍，持续 10 步。深度影响滑点，当前倍率可在 `active_mods` 和各品种的 `liquidity` 中看到。

开启随机事件后，开局以各 25% 的概率抽出 0–3 次预警。第 30 个行情步起才可能触发。常规阶段两次预警至少隔 36 步，满足间隔的每步有 1% 概率触发。最后三分钟会缩短间隔并取消概率门槛，提前结算仍可能留下未触发次数。

第 `t` 步出现预警横幅，WPF 同时播放 Windows 系统提示音。预警期间不投放普通新闻，价格仍会变动，也可能跳空。第 `t+2` 步按权重抽取 3–5 条不同机制的风险事件，每波至少有一条价格冲击，最多一条全市场价格冲击，同一个临时参数最多被一条事件修改。正常两步约 10 秒，快进或行情加速会缩短实际反应时间。

`huge_wave.total` 为抽到的总次数，`fired` 按预警开始的次数计，`left` 为尚未触发。预警给出发生时点，方向和量级要等爆发才知道。

## 平台限制类事件（随机触发）

| 事件 | 持续 | 禁什么 | 例外 |
|---|---|---|---|
| 风控审查 | 60 步（常速约 5 分钟） | 借款 | 现金为负的 60 秒自救窗口不受影响 |
| 交易所维护 | 1 步（常速约 5 秒） | 主动平仓 | 爆仓强平与比赛结束结算都不受影响 |
| 老虎机维护 | 96 步（常速约 8 分钟） | 老虎机投注 | — |

这三条都是纯随机触发，系统不会因为玩家正在关键操作而跳过。

## 外部的怜悯

参赛者与观众席之间的双向通道。**默认开启**（`TM_ASSIST` 未设置时按 `1` 处理，与 `TM_EVENTS` / `TM_FR` / `TM_SLOT` 一致；设 `TM_ASSIST=0` 关闭）。

- **开局前**：默认已经开启，免费；要关掉就设 `TM_ASSIST=0`。交互问答里也能选。
- **开局后**：v1.2.23 起已取消付费补票，`POST /assist/enable` 只会返回错误。
- 观众席界面没有开通入口：开通与否只由参赛者决定。

开启后：

| 接口 | 作用 |
|---|---|
| `POST /assist/ask` `{"text": "..."}` | 参赛者向观众席求助。整局 **3 次**，超出返回 `ok:false`。返回 `ticket` |
| `GET /assist/inbox` | 取观众席还没被取走的话；取过的不再重复投递 |
| `POST /assist/reply` `{"ticket": "a1", "text": "..."}` | 观众席回复某次求助 |
| `POST /assist/reject` `{"ticket": "a1"}` | 观众席驳回某次求助 |
| `GET /assist/pending` | 观众席 GUI 轮询用：还没回复的求助 + 最近 60 条对话记录 |

**求助不阻塞。** `POST /assist/ask` 立刻返回，参赛者接着交易，自己决定什么时候查 `GET /assist/inbox`。

观众席看到待处理的求助时，会弹出系统提示框（标题「外部的怜悯」，写明当前几条求助）并响一声提示音；GUI 按钮同时变红并显示条数。整段对话在报告里并入「场外援助」章节。

> 观众席只能回复文字；开仓平仓仍然必须由参赛者自己调接口。
