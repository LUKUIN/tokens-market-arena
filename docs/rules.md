> **中文** · [English](rules.en.md)

> 由成品包 AI 版规则整理而来；参数与人类版相同，操作方式不同。

## 怎么启动

运行时要求 **Python 3.14**（`.pyc` 与观众席控件都按 3.14 编译）。
**安装位置不限**：`run.py` 只校验版本号。本机通常在这条路径：

```
%LOCALAPPDATA%\Programs\Python\Python314\python.exe
```

**换机器时只要是 3.14，装在哪里都行**：把下面命令里的路径换成你自己的。
不确定装在哪，按这个顺序试：`python --version`（打印 3.14.x 就直接用 `python`）→ 上面那条全路径 → `dir /b "%LOCALAPPDATA%\Programs\Python" & where python`。
`py -3.14` 只在装了 py 启动器时可用，本机没有，别把它当成环境损坏的证据。
`run.py` 自己也会校验，版本不符直接退出码 2。

```bash
set TM_TRADER=GLM-5.3-深度思考-豆包
set TM_EVENTS=1
python run.py
```

服务起在 `127.0.0.1:8734`，GUI 是只读观众席。**全程不询问输入**，所有参数来自环境变量，没设置的
用默认值（`TM_TRADER=访客`、`TM_EVENTS=1`、`TM_FR=1`、`TM_SLOT=1`、`TM_ASSIST=1`）。启动顺序：读环境变量 →
起服务 → 难度盲盒（30 秒，可用 `POST /roll/stop` 叫停）→ **定档** → 计时开始 → 模型通过 HTTP 操作。

> **定档之前不能操作**：下单、借款、老虎机投注、快进都会返回「难度尚未定档」。
> 定档那一秒起全部放开，不需要额外调用。

> **无活动自动收尾**：定档后连续 `TM_IDLE_ABORT` 分钟没有任何**改变对局状态的动作**，本局自动结算，
> 报告结束原因写「无参赛者活动」。这是为误启准备的——AI 版没有操作界面，人类双击启动后
> 若不接 Agent，本会空转 45 分钟。只读观察（`/state`、`/prices`、`/rules`）不计入，
> 慢思考等待不会被提前结算。**默认 `0`（关闭）**：`launchers\开一局.bat` 设 `12`，`launchers\AI-Start.bat` 保持 `0`；
> 计时按 tick 推进，与 `bench.py` 的离线基线同一语义。

> `TM_TRADER` 经白名单过滤后写进报告文件名和报告正文，是区分参赛者的字段。
> **第一段写模型、第三段写平台**：模型 GLM-5.3 跑在豆包里 → `GLM-5.3-深度思考-豆包`。
> 写成 `Doubao-...` 是把平台当模型，报告里就只剩平台名，真正参赛的模型被抹掉。
> 人工演示用 `python run.py --interactive`，会在命令行里依次问玩家名、随机事件、【优惠融资】、【老虎机】。

也可以双击 `launchers\开一局.bat`——双击时会先问一次，5 秒内按 `Y` 才启动，不按就清理退出（防误点）。

> 本文档是 **AI 版**规则说明。人类版（`TokensMarket-OpenSource-Human`）有投资界面，
> 规则参数与本版相同。

## 难度

难度有两个维度，开局随机抽，各 5 档。它们管的是两件不同的事：

- **黑天鹅** —— 风险有多频繁
- **流动性** —— 你敢开多大仓位

### 黑天鹅 · 每 tick 每品种的跳空概率

| 档位 | 概率 | 45 分钟内单品种期望跳空 |
|---|---:|---:|
| 极低 | 0.24% | 约 1.3 次 |
| 低 | 0.60% | 约 3.2 次 |
| 中 | 1.50% | 约 8.1 次 |
| 高 | 3.75% | 约 20 次 |
| 极高 | 9.38% | 约 51 次 |

跳空幅度 2%~12%，方向随机。挂出的止损可能被直接跳过（挂 126.5 成交到 131 是常见情况）。

### 流动性 · 滑点成本

| 档位（市场深度） | 1000 万名义往返 | 占本金 100 万 |
|---|---:|---:|
| 充裕（3200 万） | 17,500 | 1.75% |
| 正常（1600 万） | 25,000 | 2.50% |
| 纤薄（800 万） | 40,000 | 4.00% |
| 枯竭（400 万） | 70,000 | 7.00% |
| 黑洞（200 万） | 130,000 | 13.0% |

上表按 1000 万名义、AURA 级点差（0.06%）算，含手续费（4,000）+ 点差（6,000）+ 滑点三部分。
**是成本占初始本金的比例**，不是占名义规模的比例。

**滑点随名义规模「平方」增长，不是线性**：成本 = `SLIP_K / (2 × 市场深度) × 名义²`，`SLIP_K = 0.0024`。
所以名义翻倍，滑点成本翻四倍。同一档位开 40M 的滑点成本是开 20M 的四倍，不是两倍。

单笔滑点率有上限：正常 1.4%，流动性冲击期间 6%。

**末期滑点上浮（v1.2.0）**：`tick ≥ 360`（最后 15 分钟）起，滑点系数从 `1.0` 线性升到 `1.5`（`tick = 540` 时打满）。这不是白送收益——**开局立刻退出收益仍是 0**，而是让「赖到最后」越来越贵：同样的仓位，末期平仓要多付最多一半的滑点。

难度会显示在窗口标题：

```
Tokens 交易市场 | 你的名字（理想情况） | 黑天鹅频率：低 | 流动性枯竭程度：纤薄
```

## 两个全局开关：优惠融资与老虎机

这两个不是随机事件，而是开局时选择的**全局开关**：整局有效。

- 只能在开局时决定；**对局一旦开始，就不能再打开**（关闭始终免费）
- 开局时开启免费

### 优惠融资

开启后：

- 借款次数**不限**（仍受 300 万贷款池与可贷额度约束）；让利只体现在目标上浮下限从 +1% 降到 +0.01%
- 借款的目标上浮区间：`+1% ~ +100%` 变成 `+0.01% ~ +100%`（**必上抬，永不减免**，最小值 0.01%）
- 上浮比例随**累计借款额**上升：首借 30 万约 4%~8%，一次借满 300 万约 35%~66%
- 拆单与一次借满等价——按累计额做梯形积分，拆成十笔不省一分钱

例：目标 200 万，借 30 万若抽到 +6%，新目标 = 200 + 1.8 = **201.8 万**

未开启时：借款次数不限，目标上浮 `+1% ~ +100%`（同样随累计额上升）。

**借款利息（原文缺失，此处补全）**：欠款按 tick 计提，利率 `0.0001`/tick（= 0.01%），
**利息计入本金继续计息（复利）**；只对当前未还余额计息，还款后基数立即下降。
一局 540 tick 满打满算的本息比约 `(1.0001)^540 ≈ 1.056`，即借 100 万挂满全局要还约 **105.6 万**。
用 `POST /repay` 提前还款可以少付这部分成本。

### 老虎机

开启后：

- 整局可投 **3 次**，单次 `1 ~ 200,000`，且不得超过下注瞬间的**可用现金**（不是权益：浮盈不算现金，用浮盈下注会把现金打成负数）
- **80%** 无所得 / **15%** 返还 5 倍 / **5%** 返还 10 倍
- 返还金额进入现金；同时目标按返还金额的 `-5% ~ 100%` 上浮

### 组合公式

```
Total = 原目标
      + Σ 每笔借款 × pct(该笔)       ← pct 随累计借款额上升
      （首借 30 万约 4%~8%，借满全池一次约 35%~66%；
        按累计额做梯形积分，拆成十笔与一次借满等价，拆单省不到钱）
      + 老虎机累计返还 × U(-5%~100%) ← 已开老虎机
```

两项独立抽取；只开一个，就只加对应的那一项。

次数用完后继续操作：返回「次数已用完，拒绝执行」。

## 快进

每局快进额度共 **15 分钟（900 秒）**。两种档位可自由混用：

| 档位 | 每次推进 | 每次后冷却 |
|---|---:|---:|
| 5 分钟 | 300 秒 | 120 秒 |
| 3 分钟 | 180 秒 | 90 秒 |

- 难度盲盒的那 30 秒不计入 45 分钟——定档的瞬间才开始计时。
- 用哪一档，就按那一档的冷却时间计时。
- 冷却期内 `POST /fastforward` 返回 `ok: false`，`ff.cool_left` 给出剩余秒数。
- 剩余额度不足以覆盖该档时，该次不执行。例如已用 `5′+3′+3′+3′ = 840` 秒，剩 60 秒，任何一档都用不了。
- 余额与冷却看 `GET /state` 的 `ff` 字段：`used` / `remain` / `cool_left` / `can5` / `can3`。
- 推进时间只有快进一条路：整局 900 秒额度、单次 300 或 180 秒、冷却 120/90 秒，不能绕开。

### 观众席窗口能做什么

AI 版的观众席是**只读**的：界面上没有下单、没有快进按钮，也没有「结束并结算」。窗口只提供两项操作：

| 操作 | 作用 |
|---|---|
| 最小化 | 把窗口收起来，对局继续跑 |
| 结束相关进程 | 停掉服务并关窗口（**会计一次异常退出**） |

正常结束本局走 `POST /quit`（结算并生成报告），不要用「结束相关进程」。
净值已达目标但手里还有仓位时，`/quit` 会被拒绝（回包 `ok:false` 并列出持仓）——先把仓位
全部 `POST /close_all` 掉再退；不平仓就只能等 45 分钟到，由引擎强制清仓。

## 常见问题

**Q: 双击 bat 后卡在「难度抽选中」不动？**
A: 那是 30 秒倒计时，`POST /roll/stop` 可以提前定格。

**Q: 窗口一直不出现？**
A: 说明卡在难度盲盒或规则窗，看看有没有被其他窗口挡住。

**Q: 报告在哪？**
A: `src/data/reports/` 下的 `.html` 文件，一局一个。抬头有随机种子与难度档位索引；
想原样复现这一局，用 `TM_SEED=<种子> TM_ROLL_INDEX=<索引>` 重开（只给种子锁不住档位）。

**Q: 想重开一局？**
A: `POST /reset`（有 30 秒冷却）。AI 版没有投资界面，也没有「重开一局」按钮。

**Q: Windows 弹警告拦住了怎么办？**
A: 源码版没有 `.pyd`，只有 `.bat` 可能被 SmartScreen 拦。右键 bat → 属性 → 勾「解除锁定」→ 确定，做一次就行。

## 挑战任务（PvZ2 关卡目标移植）

**开局第一件事**就是回答一句：**本局是否开启挑战任务？**
75 秒内 `POST /challenge/accept` 或 `POST /challenge/decline`，超时按「不开启」处理。
询问期间行情不动，对局计时和难度盲盒都还没起步，所以这段等待不占 45 分钟。

答复「开启」之后引擎才去抽难度；**难度定档那一刻**按该档阈值从池子里抽出 **3 条目标**，
与难度一起公布，本局不再改变。判定贯穿整局：破功立刻打 ×（不可逆），
达标立刻打 √（可以提前完成）。

### 任务池

| 目标 | 判定口径 | 三档阈值（低 / 中 / 高难度） |
|---|---|---|
| 两袖清风 | 全程不向贷款池借入资金 | — |
| 毫发无伤 | 全程不触发强制平仓 | — |
| 自食其力 | 不使用「外部的怜悯」求助 | — |
| 从一而终 | 同一货币对不得同时持有多空 | — |
| 精打细算 | 累计手续费不超过本金的 X | 1.5% / 1.0% / 0.7% |
| 稳如磐石 | 净值最大回撤不超过 X | 18% / 12% / 8% |
| 轻装上阵 | 同时持仓不超过 X 个货币对 | 4 / 3 / 2 |
| 留有余地 | 有持仓时保证金水平从不低于 X | 150% / 180% / 220% |
| 按兵不动 | 至少 X 笔平仓持仓满 5 tick | 1 / 2 / 3 |
| 更上层楼 | 最终净值达到目标的 X | 120% / 150% / 200% |

三条抽取规则：

- **必含至少一条结果型**（按兵不动 / 更上层楼）：三条全是「不许做某事」会把玩法压成什么都不做
- 三条互不重复，也互不矛盾
- 阈值按难度档取：`档位 = max(黑天鹅档, 流动性档)`，0~1 用宽松列、2 用中列、3 用严苛列

### 三种状态

| 标记 | 含义 |
|---|---|
| √ | 已达成（结果型可以提前达成，之后不再变化） |
| × | 已破功（过程型一旦违反即永久失败，之后不再恢复） |
| · | 进行中 |

观众席右栏「挑战任务」卡片实时显示三条目标的名称、判定口径、当前状态与破功原因；
事件流同时记带 `【挑战任务】` 前缀的条目。参赛者拒绝开启时，卡片固定显示
「本局游戏参赛者未开启挑战任务」。

三条边界：

- **询问期的等待不计入 45 分钟**：答复（或超时）那一刻才重置计时基准
- **破功不可逆**：一旦打 ×，后面再守规矩也不会变回 · 或 √
- **不改变结算与目标**：挑战任务是附加玩法，不影响目标净值、资金结算与报告口径

## 一大波预警（突发大事件）

随机事件里有一种特殊形态：**整局最多 2 次**，而且次数是掷骰定的——开局定一次，
35% 的局一次都不来、45% 来 1 次、20% 来 2 次。开局前 2.5 分钟不触发。

触发时分三段，节奏照搬《植物大战僵尸》的「一大波僵尸正在接近」：

| 段 | 发生什么 | 时长 |
|---|---|---|
| ① 预警 | 观众席屏幕正中弹出红色横幅「一大波异常行情正在接近！」并播放原版号角音效；事件流记一条 `kind=huge_wave` | 即时 |
| ② 静默 | **不投任何普通事件**，行情照常走。这两个 tick 是留给你减仓或对冲的窗口 | 2 tick = 10 秒 |
| ③ 爆发 | 一次性涌出 3~5 条冲击类事件（闪崩、瑞郎时刻、连环跳空、流动性枯竭……），同一 tick 全部生效 | 即时 |

三条边界：

- **只预告「要来」，不预告方向和量级** —— 横幅不会告诉你是利多还是利空，那要你自己判断
- **爆发池不含顺风事件** —— 抽不到「流动性充裕」「做市商回归」这类，这是刻意的，不是遗漏
- **预警本身没有数值影响** —— 全部伤害都在第三段，第二段的静默不是「缓冲」，是「倒计时」

## 平台限制类事件（随机触发）

| 事件 | 持续 | 禁什么 | 例外 |
|---|---|---|---|
| 风控审查 | 5 分钟 | 借款 | 现金为负的 60 秒自救窗口不受影响 |
| 交易所维护 | 5 秒（1 tick） | 主动平仓 | 爆仓强平与比赛结束结算都不受影响 |
| 老虎机维护 | 8 分钟 | 老虎机投注 | — |

这三条都是纯随机触发，系统不会因为玩家正在关键操作而跳过。

## 外部的怜悯

参赛者与观众席之间的双向通道。**默认开启**（`TM_ASSIST` 未设置时按 `1` 处理，与 `TM_EVENTS` / `TM_FR` / `TM_SLOT` 一致；设 `TM_ASSIST=0` 关闭）。

- **开局前**：默认已经开启，免费；要关掉就设 `TM_ASSIST=0`。交互问答里也能选。
- **开局后**：v1.2.23 起已取消付费补票，`POST /assist/enable` 只会返回错误。
- 观众席界面没有开通入口：开通与否只由参赛者决定。

开启后：

| 接口 | 作用 |
|---|---|
| `POST /assist/ask` `{"text": "..."}` | 参赛者向观众席求助。整局 **3 次**，超出返回 `no asks left (3/3)`。返回 `ticket` |
| `GET /assist/inbox` | 取观众席还没被取走的话；取过的不再重复投递 |
| `POST /assist/reply` `{"ticket": "a1", "text": "..."}` | 观众席回复某次求助 |
| `POST /assist/reject` `{"ticket": "a1"}` | 观众席驳回某次求助 |
| `GET /assist/pending` | 观众席 GUI 轮询用：还没回复的求助 + 完整对话 |

**求助不阻塞。** `POST /assist/ask` 立刻返回，参赛者接着交易，自己决定什么时候查 `GET /assist/inbox`。

观众席看到待处理的求助时，会弹出系统提示框（标题「外部的怜悯」，写明当前几条求助）并响一声提示音；GUI 按钮同时变红并显示条数。整段对话在报告里并入「场外援助」章节。

> 观众席只能回复文字；开仓平仓仍然必须由参赛者自己调接口。
