# 成本模型

> **中文** · [English](cost-model.en.md)

所有数字都来自 `tm_engine.py` 的实际常量和真实开平仓实测，不是估算。

## 四层成本

| 层 | 位置 | 计算方式 |
|---|---|---|
| **手续费** | `FEE_RATE = 0.00020` | 名义价值 × 0.02%，开仓和平仓各收一次 |
| **点差** | `PAIRS[pair]["spread"]` | 按品种分档：AURA 0.06% / FROST 0.08% / AMBER 0.10% / TIDE 0.10% / LUMEN 0.07% / NEON 0.075% / ASH 0.11% |
| **滑点** | `SLIP_K = 0.00240` | `cost = K / (2 × LIQ) × (after² − before²)`，与名义规模**平方相关** |

> v1.2.0：`tick ≥ 360` 起 `K` 本身按 `1.0 → 1.5` 线性放大（末期滑点上浮），
> 其余时刻仍为 `0.00240`。
| **隔夜利息** | `PAIRS[pair]["swap"]` | 按持仓每 tick 收一次：AURA 0.002% / FROST 0.003% / AMBER 0.004% / TIDE 0.003% / LUMEN 0.002% / NEON 0.0025% / ASH 0.0045% |

## 实测往返成本

在「流动性：纤薄」（LIQ = 8,000,000，也是未定档时的默认值）下，开仓后立刻平仓（价格不变，纯成本）：

| 名义规模 | 往返成本 | 占初始本金 100 万 |
|---:|---:|---:|
| 100 万 | 1,300 | 0.13% |
| 300 万 | 5,700 | 0.57% |
| 500 万 | 12,500 | 1.25% |
| 1000 万 | 40,000 | 4.00% |
| 2000 万 | 140,000 | 14.00% |

**关键特征**：成本率与名义规模成正比。因为滑点部分 `cost ∝ X²`，除以名义 `X` 之后变成 `cost/X ∝ X`。

## 流动性档位对成本的影响

同样的 1000 万名义，换不同流动性档位：

| 档位 | LIQ | 往返成本 | 占本金 100 万 |
|---|---:|---:|---:|
| 充裕 | 32,000,000 | 17,500 | 1.75% |
| 正常 | 16,000,000 | 25,000 | 2.50% |
| 纤薄 | 8,000,000 | 40,000 | 4.00% |
| 枯竭 | 4,000,000 | 70,000 | 7.00% |
| 黑洞 | 2,000,000 | 130,000 | 13.0% |

上表含手续费（4,000）、点差（AURA 0.06%，6,000）、滑点三部分。

**所以「流动性差」不是禁止交易，是逼你把仓位压小。**

## 达标需要多少涨幅

目标：100 万 → 200 万，需要净赚 100 万。

| 名义规模 | 需要的价格变动 | 加成本后 | 现实吗 |
|---:|---:|---:|---|
| 500 万 | 20.0% | 20.3% | 勉强（单品种 45 分钟波动 15%~25%） |
| **1000 万** | **10.0%** | **10.4%** | ✅ 最优区间 |
| 2000 万 | 5.0% | 5.7% | 成本占本金 14%，回撤容错被压得很薄 |

**1000 万名义是理论最优仓位。**

但即便如此，你还需要：方向判断正确（50/50）+ 完整吃满行情 + 承受住中间的回撤。

## 跳空为什么是最危险的

`GAP_CHANCE` 基础值 1.5%/tick/品种，幅度 2%~12%，**方向和幅度都随机**。

实测（414 tick 的样本）：

- 跳空后下一 tick 变化：`+0.33 / -0.36 / -0.29 / -0.39 / +0.19 / -0.07`（均值 -0.10%）
- **既不回归，也不延续** —— 用含跳空的序列拟合 AR(1) 得到的 beta = -0.385 是**伪回归**

**所以跳空不能预测，只能承受。**

而且**止损会被跳过**：

```
挂止损 126.5 → 实际成交 131.64（滑了 4%）
挂止损 137   → 实际成交 139.28（滑了 1.7%）
```

流动性枯竭时平仓也会有 2.3% 的滑点（`80.02 → 78.19`）。

## 强制清算与结算

普通平仓、爆仓强平、比赛结束清算走**同一条**成交路径：

```
成交价 = 中间价 ∓（半个点差 + 滑点）
费用   = 成交名义价值 × 手续费率
```

- **爆仓强平**：保证金水平跌破强平线、或追缴超时触发。点差、滑点、手续费一项不少，
  并写入成交流水（带 `forced` 标记）；报告「平仓笔数」下单独列出「其中强制平仓」。
- **比赛结束清算**：不受「交易所维护」等暂停交易状态影响；清算完成后才计算最终权益。
  最终权益 = 现金 − 欠款，**不含浮动盈亏**。
- **清算失败**：`POST /quit` 回包 `settled=false` + `warnings`，报告标题显示
  「结算异常（残留持仓 N 笔）」，不会当作正常结算。

> v1.0.12 之前，爆仓只扣手续费、不扣点差与滑点；结算平仓会被「交易所维护」拦下后
> 静默继续。历史报告的成本口径与当前版本不同，不可直接横向比较。

## 隔夜利息的累积

`LOAN_RATE_PER_TICK = 0.0001`（借款利息），`swap` 按持仓收。

一局 45 分钟 = 540 tick。如果全程持有 700 万名义：

```
700 万 × 0.003%（平均 swap）× 540 tick ≈ 113,400
```

**这相当于初始本金的 11.3%** —— 光利息就能把一局吃掉。

实测数据（真实对局）：

| 项目 | 金额 |
|---|---:|
| 手续费 | 17,096 |
| 隔夜利息 | 59,379 |
| **合计** | **76,475** |

在亏损 32.38% 的那局里，**手续费 + 利息占了总亏损的 23.6%**。

四分之一以上的亏损不是交易做错，是**停留成本**。

## 结论

**这个游戏在数学上是负和游戏。**

- 纯随机押注：期望为负，胜率 3%~5%
- 有纪律执行（小仓位、少交易、抓极端偏离）：胜率可提到 10%~15%

这就是为什么它适合测试 AI —— **它不给「算得快」任何优势，只奖励「纪律好」**。
